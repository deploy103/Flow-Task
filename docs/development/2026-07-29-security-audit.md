# 2026-07-29 추가 16단계: 애플리케이션 보안 감사

## 점검 범위

- `npm audit --audit-level=low`로 직접·전이 의존성 취약점 확인
- 인증 세션, 비밀번호·메일 토큰, 권한 검사, 파일 저장 경로, 외부 URL 정책 확인
- 상태 변경 API의 Origin 검사와 요청 크기 제한 확인
- 보안 헤더와 Content Security Policy 확인
- 저장소의 자격 증명 패턴과 운영 예제의 비밀 값 기본 설정 확인

## 발견 및 조치

- 의존성 감사 결과 알려진 취약점은 0건이었다.
- 기존 CSP의 `script-src 'unsafe-inline'`은 XSS 발생 시 인라인 스크립트 실행을 막지 못한다.
- 문서 요청마다 CSPRNG nonce를 만들고 Next.js 렌더링 요청과 응답 CSP에 같은 nonce를 전달하도록 변경했다.
- 정적으로 미리 생성된 HTML에 nonce가 누락되지 않도록 루트 레이아웃을 요청 시점 렌더링으로 전환했다.
- 외부 요청의 `x-nonce`와 CSP 헤더는 서버가 항상 새 값으로 덮어쓴다.
- 운영 CSP에서는 `unsafe-inline`과 `unsafe-eval`을 허용하지 않는다. 개발 모드에서만 Next.js 개발 런타임을 위해 `unsafe-eval`을 허용한다.
- 교차 출처 자원 정책과 Origin 격리 헤더를 추가했다.

## 남은 운영 확인

- 17단계에서 실제 서버의 TLS, 방화벽, 프록시 전달 헤더와 컨테이너 권한을 점검한다.
- 18단계에서 운영체제 기본 보안 12개 항목을 체크리스트로 대조한다.
