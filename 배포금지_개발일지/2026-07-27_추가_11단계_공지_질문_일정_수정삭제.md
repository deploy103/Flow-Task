# 추가 11단계 개발일지 — 공지·질문·일정 수정과 삭제

## 권한 정책

- 공지와 일정은 조직 관리자 또는 시스템 관리자만 수정·삭제한다.
- 질문은 현재 활성 소속인 작성자와 조직/시스템 관리자만 수정·삭제한다.
- 모든 변경 액션은 URL이 아닌 서버에서 조직 ID, 대상 ID, 활성 상태와 권한을 다시 검증한다.

## 구현

- 공지의 제목, Markdown 내용, 중요도, 공개 대상을 수정하고 삭제할 수 있다.
- 공지가 수정되면 이전 확인 기록을 초기화해 변경된 내용을 다시 확인하게 한다.
- 선택 공개 대상은 현재 활성 구성원인지 검증하고 트랜잭션에서 교체한다.
- 질문의 분야, 제목, 내용, 시도·오류·코드, 관련 과제를 수정할 수 있다. 비공개 경계가 변하지 않도록 게시판 종류는 수정 대상에서 제외했다.
- 질문 삭제 시 제목 재입력을 요구하며, 답변·감사 이력 무결성을 위해 물리 삭제 대신 숨김 처리한다.
- 기존 일정 수정·보관 기능을 사용자에게 일관된 `수정·삭제` 흐름으로 표시했다.
- 공지, 질문, 일정 수정과 삭제를 모두 감사 로그에 남긴다.

## 검증

- 질문 작성자/관리자/비활성 사용자 편집 권한 단위 테스트
- 공지 수정 ID 스키마 및 기존 입력 경계 테스트
- TypeScript, ESLint, 전체 테스트, 프로덕션 빌드
