# 추가 9단계 개발일지 — 계정과 동아리 관리 보완

## 구현

- 내 정보 화면에서 기본 프로필, 비밀번호와 로그인, 가입 동아리를 구분해 관리하도록 재구성했다.
- 비밀번호 변경은 현재 비밀번호를 서버에서 확인하고 새 비밀번호 일치 여부와 길이를 다시 검증한다.
- 비밀번호 확인 시 계정·접속 출처·전체 요청 횟수 제한을 적용해 탈취된 세션을 통한 반복 추측을 제한한다.
- 비밀번호 변경 후 모든 세션과 미사용 비밀번호 재설정 토큰을 폐기하고 새 비밀번호로 다시 로그인하게 한다.
- 공통 헤더 로그아웃 버튼에 넓은 화면용 텍스트를 추가하고 내 정보 화면에도 명확한 로그아웃 동선을 제공한다.
- 가입 동아리별로 정확한 동아리 이름을 입력한 뒤 탈퇴할 수 있게 했다.
- 마지막 활성 동아리 관리자는 탈퇴를 차단하고, 관리자 역할을 다른 구성원에게 먼저 부여하도록 안내한다.
- 탈퇴 시 해당 동아리의 부서 소속을 제거하고 활성 멘토 관계를 종료하며 조직 소속을 비활성화한다.
- 프로필 수정, 비밀번호 변경과 동아리 탈퇴 결과를 내부 오류 없이 구체적인 안내로 표시한다.

## 권한과 데이터 보존

- 동아리 ID만 신뢰하지 않고 현재 로그인 사용자의 활성 소속을 트랜잭션 안에서 다시 조회한다.
- 탈퇴 대상은 현재 사용자로 고정하며 클라이언트가 사용자 ID를 전달하지 않는다.
- 기존 제출물, 공지 확인, 질문과 감사 기록은 참조 무결성을 위해 보존한다.
- 비밀번호 원문과 현재 비밀번호 검증 결과는 저장하거나 로그에 기록하지 않는다.

## 테스트

- 비밀번호 변경 입력, 현재 비밀번호 확인, 전체 세션 폐기 테스트
- 마지막 동아리 관리자 탈퇴 차단 정책 테스트
- 본인 소속 비활성화, 부서 소속 제거와 멘토 관계 종료 액션 테스트
- 동아리 이름 확인 입력 스키마 테스트
- 전체 타입 검사, ESLint, 단위 테스트, 프로덕션 빌드와 의존성 감사
