# 추가 7단계 개발일지 — 서비스 문구 개선

## 점검 기준

- 추상적인 홍보 문구보다 사용자가 실제로 할 수 있는 행동을 설명한다.
- 친근함을 과도하게 강조한 감탄형·질문형 표현을 줄인다.
- 버튼, 빈 상태와 안내 문구는 다음 행동을 바로 알 수 있게 작성한다.
- 같은 화면에서 존댓말 어미와 기능 용어를 일관되게 사용한다.

## 구현

- 공개 메인 화면을 공지, 과제, 제출 확인 등 실제 제공 기능 중심으로 다시 작성했다.
- 로그인과 회원가입 화면 제목을 기능명으로 바꾸고 필요한 입력과 다음 절차를 설명했다.
- 대시보드와 조직 화면의 인사말·기본 설명을 현재 상태를 알려 주는 문구로 변경했다.
- 공지와 과제의 빈 상태 문구를 간결한 서술형으로 통일했다.
- 공개 기능 및 이용 순서 문구가 모호한 표현으로 되돌아가지 않도록 회귀 테스트를 추가했다.
- 검사 중 확인된 `brace-expansion` 고위험 권고를 패치 버전으로 고정했다. 기존 ESLint 플러그인이 사용하는 CommonJS 함수 형식은 설치 후 결정적인 호환 어댑터를 적용하며, 의존성 정책 테스트로 고정을 검증한다.

## 보안과 데이터 영향

- 표시 문구만 변경하며 인증, 권한, 데이터 조회와 저장 로직은 변경하지 않는다.
- 운영 환경값이나 개인정보를 추가하지 않는다.

## 검증

- `npm run typecheck`
- `npm run lint`
- `npm test`
- `npm run build`
